CRITIQUE: The suggestion to use a pre-computed `skip_table` would require building a table of size O(n) for every input string, which is wasteful and doesn't scale well. It also fails to account for the fact that whitespace skipping is often short-circuited and doesn't always traverse the entire string, so a full lookup table would be overkill. Additionally, it doesn't consider that the current `_skip_ws` is already quite fast due to the `frozenset` lookup and that the table would need to be built per-call, negating any performance gains.

The table should be built at the start of `parse`, and all `_skip_ws` calls should use it, while maintaining the original logic for correctness and handling edge cases.
