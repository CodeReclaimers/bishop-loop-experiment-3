CRITIQUE: The suggestion to replace the `while` loop in `_skip_ws` with a regex search would fail because the regex pattern `[ \t\n\r]*` only matches zero or more whitespace characters, not the *first non-whitespace character*. This means it would skip to the end of a run of whitespace but not advance the position past it correctly, leading to incorrect parsing. Additionally, the regex approach could be slower than the current loop for short runs of whitespace due to regex overhead.

STEELMAN: The steelman is to use `_WS_PATTERN.search(text, pos)` to find the first non-whitespace character, then advance the position to that point. This preserves the intent of eliminating per-character checks while ensuring correct behavior by using the regex result to jump directly to the end of whitespace sequences.
