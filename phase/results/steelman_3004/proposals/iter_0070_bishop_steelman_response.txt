CRITIQUE: The suggestion to precompute a `ws_table` array assumes that all whitespace sequences are short and that the table can be indexed directly, but this fails for large inputs or when whitespace occurs in patterns that don't fit the table structure. It also ignores that the table would need to be recomputed for every new input string, making it infeasible for dynamic parsing. Additionally, it doesn't consider memory overhead and cache locality implications of a large lookup table.

STEELMAN: A better approach is to compute a single lookup table once per parse call, where each entry maps an input position to the next non-whitespace character using a fast scan. This can be implemented by scanning the input once and building a table of next non-whitespace positions, which allows O(1) skipping without recomputing or storing redundant data. The table should be built lazily and reused for the current parse.

def _build_ws_table(text: str) -> list[int]:
    """Build a lookup table mapping each position to the next non-whitespace position."""
    n = len(text)
    ws_table = [0] * n
    pos = n - 1
    while pos >= 0:
        if text[pos] in _WS_CHARS:
            ws_table[pos] = ws_table[pos + 1] if pos + 1 < n else n
        else:
            ws_table[pos] = pos
        pos -= 1
    # Adjust the table so that ws_table[i] points to the next non-whitespace position
    for i in range(n - 2, -1, -1):
        if text[i] not in _WS_CHARS:
            ws_table[i] = i
        else:
            ws_table[i] = ws_table[i + 1]
    return ws_table
