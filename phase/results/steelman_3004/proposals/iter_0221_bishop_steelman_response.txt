CRITIQUE: The suggestion to use a `skip_table` for whitespace skipping is problematic because it would require precomputing a table of size O(n) where n is the length of the input string, which is memory-inefficient and defeats the purpose of optimizing for speed. Additionally, it assumes the table can be reused across calls, but since the input string changes with each parse, a new table must be built each time, making the approach impractical.

STEELMAN: A better approach is to precompute a single skip table for the entire input string once, then reuse it across all whitespace skips. This avoids repeated scanning of whitespace and allows O(1) lookups. The table should be computed at the start of parsing and used for all subsequent `_skip_ws` calls, preserving correctness while improving performance.

    n = len(text)
