Using `re.search` would require parsing the entire whitespace run, which could be inefficient and doesn't integrate well with the existing stateful parsing logic. Additionally, the regex approach would not preserve the exact position tracking needed for error reporting and would complicate the parsing flow.

The key is to use the regex to find the end of the whitespace run and advance the position accordingly, without changing the structure of the calling functions.
