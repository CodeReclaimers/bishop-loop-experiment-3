CRITIQUE: The suggestion to use a precomputed skip table would require building a table of size O(n) for every parse, which is wasteful and doesn't reduce the asymptotic complexity. It also fails to account for the fact that whitespace skipping is not a uniform operation—it depends on the actual content and position, so a static table won't capture the dynamic nature of the parsing. Additionally, it introduces memory overhead and complexity without clear benefit over the existing optimized linear approach.

STEELMAN: A better approach would be to precompute a "skip table" that maps each starting index to the next non-whitespace position, but only build this once per parse call and store it in a local variable. This avoids repeated character-by-character checks while maintaining correctness, and the table size is still O(n) but amortized across the parse, making it a practical optimization for parsers that do frequent whitespace skipping.

def _build_skip_table(text: str) -> list[int]:

    skip_table = [0] * n
    i = n - 1
