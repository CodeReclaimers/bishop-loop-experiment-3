CRITIQUE: The suggestion to precompute a `_compute_next_non_ws` table is unworkable because it would require a massive lookup table (one entry per possible input position) that's impractical to construct and would consume enormous memory. Additionally, it fails to account for the fact that whitespace skipping is not a fixed offset operation—it depends on the actual content of the input string. The approach also doesn't consider that the table would need to be built at runtime for each input, negating any performance gains.

STEELMAN: A better approach is to precompute a "next non-whitespace" index table for the entire input string, where each index maps to the position of the next non-whitespace character. This can be done efficiently in O(n) time once, and then `_skip_ws` becomes a simple O(1) table lookup. This preserves the spirit of eliminating loops while maintaining correctness and performance.
