CRITIQUE: The suggestion to use binary search over precomputed whitespace positions is flawed because it assumes a static list of whitespace indices that would need to be recomputed for every input, making it O(n) setup cost. It also doesn't account for the fact that whitespace skipping is typically done in a streaming fashion, not in batched precomputed steps, and would require maintaining global state or passing around indices, which breaks the current clean functional interface.

STEELMAN: A better approach is to precompute a list of all whitespace character positions in the input string once, then use binary search to find the next non-whitespace character, avoiding repeated linear scans. This maintains the current interface by computing the whitespace indices once per parse call, and the binary search allows O(log m) skipping where m is the number of whitespace characters, while still using O(1) set lookups for membership checks.

def _skip_ws(text: str, pos: int, whitespace_indices: list[int]) -> int:
    # Binary search for the next non-whitespace character
    left, right = 0, len(whitespace_indices) - 1
    while left <= right:
        mid = (left + right) // 2
        idx = whitespace_indices[mid]
        if idx <= pos:
            left = mid + 1
        else:
            right = mid - 1
    # `left` now points to the first whitespace index >= pos
    if left < len(whitespace_indices) and whitespace_indices[left] == pos:
        # Skip all consecutive whitespace characters starting at pos
        while left < len(whitespace_indices) and whitespace_indices[left] == pos:
            pos += 1
            left += 1
        # Continue binary search to find next non-whitespace
        return _skip_ws(text, pos, whitespace_indices)
    return pos
