CRITIQUE: The suggestion to replace the character-by-character loop with a precomputed `ws_table` is unworkable because it would require building a table of size proportional to the input length, which is inefficient in both space and time. It also fails to account for the fact that whitespace skipping is not a simple "jump to next non-whitespace" operation — it needs to handle all whitespace characters and maintain position tracking. Additionally, the suggestion omits how to handle the case where the input is entirely whitespace or when the parser needs to backtrack or re-scan.
STEELMAN: A better approach is to build a lookup table once per parse run that marks the end of each whitespace run, allowing O(1) jumps to the next non-whitespace character. This table can be built in a single pass over the input and avoids re-scanning by precomputing all whitespace boundaries. The key is to compute the table once and reuse it, not to eliminate the logic entirely.

def _build_ws_table(text: str) -> list[int]:
    """Build a table where ws_table[i] gives the index of the next non-whitespace character starting at i."""
    n = len(text)
    ws_table = [0] * n
    i = n - 1
    while i >= 0:
        if text[i] in _WS_CHARS:
            if i == n - 1:
                ws_table[i] = n
            else:
                ws_table[i] = ws_table[i + 1]
        else:
            if i == n - 1:
                ws_table[i] = i + 1
            else:
                ws_table[i] = i + 1
        i -= 1
    return ws_table
