Replace the repeated string concatenations that build the output string (e.g., `out = out + "\f"` and `out = out + c` in the escape‑sequence handling of `_parse_value`) with a list‑based accumulation, appending characters to a mutable list and joining the list to a single string at the end of the parsing step. This avoids the O(n²) cost of building strings incrementally and reduces memory churn while keeping the parser’s correctness intact. The same principle can later be applied to the string‑building in `_parse_object` if needed, though the current direct‑assignment dict construction is already optimal.
