It also ignores that the current implementation already uses `int`/`float` conversion, so the performance benefit would be minimal at best. Additionally, it doesn't consider that the loop is necessary to detect malformed numbers like `1.2.3` or `1e` during parsing, which a simple slice-and-convert approach would miss.

STEELMAN: The steelman is to extract the full number substring (including sign, decimal point, and exponent) in one step, then validate that it's a syntactically valid number before converting it to `int` or `float`. This preserves the performance improvement of avoiding character-by-character scanning while maintaining correctness by leveraging built-in validation and conversion, and still supports the existing error messages and parsing logic.
