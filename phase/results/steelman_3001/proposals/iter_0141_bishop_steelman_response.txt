CRITIQUE: The suggestion to replace the while-loop in `_skip_ws` with a single `text.find` call is problematic because `text.find` only finds the first non-whitespace character, not the position after all leading whitespace. This would leave the parser stuck at the first whitespace character instead of advancing past all of it. Additionally, it doesn't handle the case where the entire string consists of whitespace, which should raise an error.

STEELMAN: The steelman version would use `text.find` to locate the first non-whitespace character, but then we must still advance the position past all consecutive whitespace characters by counting them manually or using a regex-based approach. A better approach is to use `text.find` to locate the first non-whitespace character and then advance by the number of whitespace characters between the current position and that character.
