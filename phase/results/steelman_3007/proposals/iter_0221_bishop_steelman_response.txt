CRITIQUE: The suggestion to use a pre-computed skip table assumes that the entire input can be preprocessed, which would require building a table of size O(n) for every possible input. This is infeasible for large inputs and contradicts the streaming nature of the parser. Additionally, it doesn't address the fact that whitespace skipping is not a one-time operation but happens repeatedly during parsing, so a static table won't help with dynamic parsing paths.

STEELMAN: A better approach is to precompute a "skip table" that maps each starting index to the next non-whitespace character's index, but only for the specific input being parsed. This table can be built once and reused for the current parse, avoiding repeated character-by-character checks while maintaining the streaming behavior.

def _build_skip_table(text: str) -> list[int]:
