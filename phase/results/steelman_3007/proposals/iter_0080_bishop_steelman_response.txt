CRITIQUE: The suggestion fails to account for the fact that whitespace runs can be of arbitrary length, so precomputing a lookup array would require O(n) space and time to build, negating any benefits of O(1) lookups. It also doesn't consider that the parser may need to skip over multiple whitespace characters in a single call, which a simple array lookup cannot efficiently handle without redundant computation. Additionally, the approach doesn't address how to properly handle the edge case where the array index might point beyond the string or into the middle of a whitespace run.
STEELMAN: The steelman version would compute a "next_non_ws" array that maps each position to the index of the first non-whitespace character after a contiguous whitespace run starting at that position, but only for positions that actually begin whitespace runs. This allows O(1) skipping by using the array when we're at the start of a whitespace run, falling back to the existing method otherwise, and avoiding the O(n) cost of building a full array.
