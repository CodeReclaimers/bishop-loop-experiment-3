CRITIQUE: The suggestion to use a precomputed skip table assumes that the table can be efficiently built and that it will always be faster than a simple while loop. However, building such a table requires scanning the entire input string once, which is expensive, and the table itself consumes O(n) space. Additionally, the table lookup would require bounds checking and may not be faster than a simple loop due to cache behavior and branch prediction.
STEELMAN: A better approach is to precompute a skip table that maps each starting position to the next non-whitespace character, but only build it when needed and reuse it across multiple parsing operations. This avoids the overhead of repeated table construction while maintaining O(1) skipping. The table can be built once per input string and used to jump directly to the next non-whitespace character.

# Precomputed skip table for whitespace
def _build_skip_table(text: str) -> list[int]:
    n = len(text)
    skip_table = [0] * n
    pos = n - 1
    while pos >= 0:
        if text[pos] in _WS_CHARS:
            skip_table[pos] = skip_table[pos + 1] if pos + 1 < n else n
        else:
            skip_table[pos] = pos
        pos -= 1
    return skip_table
