CRITIQUE: The suggestion to replace the while-loop in `_skip_ws` with `text.find` is unworkable because `text.find` only locates the first occurrence of any character from a set, not the first non-whitespace character. It also doesn't handle the case where the entire remainder of the string is whitespace, which would cause `find` to return the length of the string and not properly advance the position. Additionally, `text.find` would not be faster than the existing loop for short whitespace runs, and would likely be slower due to overhead.

STEELMAN: A better approach would be to use `str.lstrip()` with the whitespace set or to leverage `str.translate()` and `str.maketrans()` to efficiently skip leading whitespace. However, if we want to stick close to the original idea of using a C-level search, we can use `text.find` with a custom helper that scans for the first non-whitespace character using the set, and then advance the position accordingly.
