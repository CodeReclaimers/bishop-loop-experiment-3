Replace each manual `pos += 1` loop that advances the index one character at a time with a call to `_skip_ws` (or its `find`‑based version) so that whitespace runs are jumped over in a single pass. This removes the repeated, character‑by‑character iteration that dominates the runtime and lets the parser locate the next non‑whitespace token in O(1) per segment rather than O(k) where k is the length of the whitespace block. The correction is kept because `_skip_ws` already validates that the next character is the expected one, preserving all existing logic.
