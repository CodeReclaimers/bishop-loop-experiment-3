Replace the whitespace‑skipping sections that use `text.find('\0', pos)` or a regular‑expression match with a simple loop that checks `while pos < len(text) and text[pos] in _WS_CHARS: pos += 1`. This eliminates the overhead of a regex engine and a costly `find` call per character, letting the loop directly iterate over the set of whitespace characters, which is O(1) per character. The rest of the parser already uses the same logic for most cases, so the change keeps correctness while removing the dominant slow path.
