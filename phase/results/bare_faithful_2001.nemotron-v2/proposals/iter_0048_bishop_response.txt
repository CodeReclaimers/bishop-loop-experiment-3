Replace the per‑character whitespace‑skipping loops in `parse` and `_parse_object` with a single `str.find` call that jumps to the next non‑whitespace character, using the current `_WS_CHARS` set to locate the next matching character at once. This eliminates the O(1) membership checks per character and reduces the constant‑factor cost of incrementing `pos` one step at a time. The change keeps the same correctness because it still stops at the first non‑whitespace character.
