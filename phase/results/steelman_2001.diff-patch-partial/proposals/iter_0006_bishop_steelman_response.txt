CRITIQUE: The suggestion to replace `_skip_ws` with a simple loop using `ord(text[pos])` and a pre-computed set is problematic because it doesn't account for the fact that `ord()` on Unicode characters can be slower than regex matching in some cases, and the loop would still need to check each character individually. Additionally, it ignores that the current implementation uses `re.compile` once and reuses it, so the overhead of regex compilation is not repeated per call — only the matching logic is repeated.

STEELMAN: A better approach is to precompute a set of whitespace characters (including common ones like space, tab, newline, and carriage return) and use a tight loop that advances `pos` while `text[pos]` is in that set, avoiding regex entirely. This preserves the performance benefit of avoiding regex overhead while ensuring correctness and maintaining a clean, readable loop.
