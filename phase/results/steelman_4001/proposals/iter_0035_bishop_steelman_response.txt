CRITIQUE: The suggestion to use regex for number parsing is problematic because it doesn't address the core inefficiency of the current implementation, which is that `_parse_number` still needs to scan the input character-by-character to find the number boundaries. Using a regex would require matching the entire number pattern, but the current approach already does this via `_NUMBER_RE.match(text, pos)`. Additionally, regex matching introduces overhead that may not be beneficial for short numbers and could be slower than the existing optimized `int()`/`float()` conversion.

STEELMAN: A better approach would be to precompile the regex once and reuse it, as suggested, but also to avoid redundant parsing by leveraging the regex match result directly to extract and convert the number, ensuring that the parsing loop is not unnecessarily repeated for each digit.
