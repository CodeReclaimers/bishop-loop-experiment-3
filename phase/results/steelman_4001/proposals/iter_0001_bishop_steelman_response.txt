It also doesn't address the core issue that the current implementation does unnecessary work like rebuilding collections on each step. Additionally, regex solutions may not handle all edge cases of JSON number formats correctly without careful crafting.

STEELMAN: A better approach would be to use a compiled regex pattern to identify the full number token in one go, then parse it using built-in functions like `int()` or `float()`, which are highly optimized and handle all valid JSON number formats correctly. This avoids the per-character checks while leveraging Python's fast native number parsing.

import re

# Precompile the regex for number parsing to avoid repeated compilation cost
_NUMBER_RE = re.compile(r'-?(?:0|[1-9]\d*)(?:\.\d+)?(?:[eE][+-]?\d+)?')

def _parse_number(text: str, pos: int) -> tuple[float | int, int]:
    # Find the full number token using regex
    match = _NUMBER_RE.match(text, pos)
    if not match:
        raise JSONParseError(f"bad number at {pos}")
    s = match.group(0)
    pos = match.end()
    # Use built-in conversion which is highly optimized
    if '.' in s or 'e' in s.lower():
        return float(s), pos
    return int(s), pos
