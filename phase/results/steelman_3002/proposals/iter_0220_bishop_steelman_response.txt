CRITIQUE: The suggestion to use binary search on a pre-computed list of whitespace indices is fundamentally flawed because it doesn't account for the fact that whitespace skipping is not a one-time operation but happens repeatedly during parsing at various positions. Binary search would require maintaining and updating this list dynamically, which adds complexity and overhead. Additionally, the O(log n) improvement is theoretical and may not outweigh the cost of building and maintaining the index list, especially for small to medium inputs where linear scanning is faster due to cache locality.

STEELMAN: A better approach would be to precompute a "whitespace skip table" that maps each position in the input string to the next non-whitespace character index. This table can be built once at the start of parsing and then used for O(1) lookups, avoiding repeated scanning while keeping the implementation simple and cache-friendly.

def _build_skip_table(text: str) -> list[int]:
    """Build a table mapping each index to the next non-whitespace index."""
    n = len(text)
    skip_table = [0] * n
    pos = n
    for i in range(n - 1, -1, -1):
        c = text[i]
        if c in ' \t\n\r':
            skip_table[i] = pos
        else:
            skip_table[i] = pos = i + 1
    return skip_table
