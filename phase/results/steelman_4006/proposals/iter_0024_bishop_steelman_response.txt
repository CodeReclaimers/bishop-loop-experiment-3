CRITIQUE: The suggestion to use a `StringBuilder` is naive because Python strings are immutable, so there's no true `StringBuilder` equivalent. Simply switching from `list` + `''.join()` to a `str` accumulator with `+=` would actually hurt performance due to repeated string allocations. The suggestion doesn't address the real bottleneck which is the character-by-character parsing and escape handling logic.

STEELMAN: The steelman is to optimize `_parse_string` by using a `list` to collect characters and then joining once at the end, which is already being done in the current implementation. However, we can improve the escape handling logic to reduce redundant checks and improve the inner loop efficiency by precomputing the length of escaped sequences and avoiding repeated `pos` increment operations.
