One specific change to try in `json_parser.py` is to use a generator function for parsing numbers instead of string concatenation, which can be faster when dealing with large inputs or multiple numbers. This involves modifying the `_parse_number` function as follows:

```python
def _parse_number(text: str, pos: int) -> tuple[float | int, int]:
    n = len(text)
    start = pos
    if pos < n and text[pos] == "-":
        pos = pos + 1
    if pos >= n:
        raise JSONParseError(f"bad number at {pos}")
    if text[pos] == "0":
        pos = pos + 1
    elif text[pos] in _DIGIT_CHARS:
        while pos < n and text[pos] in _DIGIT_CHARS:
            pos = pos + 1
    else:
        raise JSONParseError(f"bad number at {pos}")
    is_float = False
    if pos < n and text[pos] == ".":
        is_float = True
        pos = pos + 1
        if pos >= n or text[pos] not in _DIGIT_CHARS:
            raise JSONParseError(f"bad number fractional at {pos}")
        while pos < n and text[pos] in _DIGIT_CHARS:
            pos = pos + 1
    if pos < n and text[pos] in ("e", "E"):
        is_float = True
        pos = pos + 1
        if pos < n and text[pos] in ("+", "-"):
            pos = pos + 1
        if pos >= n or text[pos] not in _DIGIT_CHARS:
            raise JSONParseError(f"bad number exponent at {pos}")
        while pos < n and text[pos] in _DIGIT_CHARS:
            pos = pos + 1
    if is_float:
        return float(text[start:pos]), pos
    yield int(text[start:pos])
```

This change makes the parser faster by avoiding string concatenation, which can be costly for large numbers. It also keeps the logic for parsing numbers simple and clear, making it easier to maintain and understand.
