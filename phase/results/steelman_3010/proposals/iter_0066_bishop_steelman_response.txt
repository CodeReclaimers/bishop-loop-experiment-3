CRITIQUE: The suggestion to replace the manual while-loop in `_skip_ws` with a regex call would break the function's contract because `_skip_ws` is designed to return the position *after* skipping whitespace, but regex matching doesn't naturally return that; it returns a match object that needs to be processed. Additionally, using a regex for such a simple operation introduces overhead from regex compilation and matching that may not be justified for small amounts of whitespace.
STEELMAN: A better approach is to use the compiled regex `_WS_PATTERN` to find the next non-whitespace character by matching zero or more whitespace characters from the current position, then advancing `pos` to the end of that match. This preserves the performance gains from regex while maintaining correctness and avoiding per-character iteration.
