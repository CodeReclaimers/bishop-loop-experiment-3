Using `search()` would skip the regex's ability to match the longest possible sequence in one go, and the regex engine's overhead would likely exceed the benefit of avoiding the loop. Additionally, the regex pattern `[ \t\n\r]*` matches zero or more whitespace characters, so it would not correctly handle the case where the input ends in whitespace.

STEELMAN: A better approach is to use `re.match()` instead of `re.search()` to match the longest sequence of whitespace characters starting at the given position, then advance the position by the match length.
