The main bottleneck is the per‑character string concatenation in `_parse_string` where `out = out + c` (and the same pattern in the escape‑sequence handling) creates a new string on every iteration. Replace this with a list accumulator that appends each character (including those built from escaped sequences) and returns `''.join(list)` at the end, eliminating repeated allocations. This single change should cut down the overhead without affecting correctness.
