The bottleneck occurs in `_parse_string` where the parser repeatedly builds a string with `out = out + c` and `out = out + chr(cp)`, causing quadratic allocation overhead; change this to collect characters in a list and perform a single `''.join` at the end, which reduces repeated string copying to linear time. This change applies to both normal character appends and Unicode escape handling, preserving correctness while dramatically speeding up string construction.
