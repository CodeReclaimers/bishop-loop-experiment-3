CRITIQUE: Using a compiled regex for whitespace skipping would be suboptimal because it introduces regex overhead and complexity when simple character-by-character iteration is already highly optimized. The suggestion ignores that the current `_skip_ws` function is already efficiently implemented with a tight loop and precomputed set lookups. Additionally, regex matching isn't necessarily faster than the existing O(1) set membership checks, especially for small inputs.

STEELMAN: A better approach would be to use a compiled regex to skip *multiple* whitespace characters at once, but only when there's a significant run of whitespace. This avoids the overhead of repeated small checks while still maintaining simplicity and correctness. The regex should be used as a fast path for large contiguous whitespace sections, falling back to the existing logic for smaller or irregular whitespace patterns.
