CRITIQUE: Using a regex to skip whitespace would introduce significant overhead from regex compilation and matching, especially since `_skip_ws` is called very frequently during parsing. It would also break the existing inline loop optimization that's already quite efficient. Additionally, regex-based skipping doesn't integrate well with the current position-tracking approach and could complicate error reporting or lead to incorrect positions being returned.

STEELMAN: A better approach is to use a precompiled regex to skip whitespace in one go, but only when a large amount of whitespace is expected, and fallback to the fast inline loop for small skips. This preserves performance for common cases while still leveraging regex for bulk skipping, and maintains the existing API and error handling behavior.
