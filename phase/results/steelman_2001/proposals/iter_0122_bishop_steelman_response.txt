Additionally, the regex would need to handle complex cases like Unicode escapes and exponent notation, which could introduce performance overhead or correctness issues when combined with the existing parsing state.

STEELMAN: The steelman is to use a regex to efficiently validate and extract the numeric or hex escape substring, but still maintain the incremental parsing flow by using the regex match length to advance the `pos` pointer. This preserves the existing control flow while eliminating per-character checks, and the regex should be compiled once and reused for performance.

import re

# Precompile regex for number validation
_NUMBER_RE = re.compile(r'-?(?:0|[1-9]\d*)(?:\.\d+)?(?:[eE][+-]?\d+)?')

def _parse_number(text: str, pos: int) -> tuple[float | int, int]:
    n = len(text)
    start = pos
    # Use regex to match the full number
    match = _NUMBER_RE.match(text, pos)
    if not match:
        raise JSONParseError(f"bad number at {pos}")
    pos = match.end()
    s = text[start:pos]
    if '.' in s or 'e' in s.lower():
        return float(s), pos
    return int(s), pos
