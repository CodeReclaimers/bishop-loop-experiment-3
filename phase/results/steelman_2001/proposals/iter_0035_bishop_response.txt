The main bottleneck is the per‑character string concatenation used to build string and object values, which forces repeated allocation and copying. Replace the repeated `out.append` and string‑building in `_parse_string` and the escape‑handling loop with an in‑memory list of characters that is joined once at the end of each parsing step, eliminating the costly string concatenations while preserving the final output. This change will speed up both string and object construction without altering the public API or correctness.
