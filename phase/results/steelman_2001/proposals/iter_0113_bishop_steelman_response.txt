CRITIQUE: The suggestion to preprocess all whitespace into a compact string would break the parser's ability to track accurate positions for error messages, since the original positions would be lost during normalization. Additionally, it would require reprocessing the entire input string multiple times, which could be inefficient for large inputs with sparse whitespace. Finally, the approach doesn't account for the fact that `_skip_ws` is called in many different contexts with varying expectations about how much whitespace to skip.

STEELMAN: A better approach is to precompile a regex that matches one or more whitespace characters and use it to find and skip whitespace in a single pass, preserving position tracking while reducing Python-level loop overhead. This allows us to still call `_skip_ws` but with a more efficient internal implementation that uses regex matching instead of character-by-character loops.
