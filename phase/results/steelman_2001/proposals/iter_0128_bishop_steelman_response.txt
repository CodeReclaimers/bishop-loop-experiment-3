CRITIQUE: The suggestion to replace `_skip_ws` with a regex match would break the incremental parsing model, since regex matching doesn't return the new position after the match — it only tells you whether a match occurred. This would require rewriting the entire parsing logic to handle regex results properly, which is not a simple drop-in optimization. Additionally, regex matching is slower than a tight loop for small amounts of whitespace, and could introduce performance regressions in cases with minimal whitespace.

STEELMAN: The steelman version of the idea is to precompile a regex that matches one or more whitespace characters starting at a given position, and use it to efficiently skip whitespace by updating the position to the end of the match. This preserves the existing parsing logic while leveraging the performance of compiled regexes for the whitespace skipping, and should be done in a way that maintains the same return position semantics as the original function.
