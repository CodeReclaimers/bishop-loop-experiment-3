CRITIQUE: The suggestion to use a list of tuples instead of incremental dict updates would break the error handling logic, since the current implementation raises errors for duplicate keys during parsing, not after. Also, it would require a second pass to build the dict, adding overhead and complexity. The idea is naive because it doesn't account for the need to validate key uniqueness during parsing.

STEELMAN: The steelman version would collect key-value pairs in a list during parsing, but still validate key uniqueness on-the-fly by checking if a key already exists before appending, thus preserving error semantics while reducing dict reconstruction overhead.
