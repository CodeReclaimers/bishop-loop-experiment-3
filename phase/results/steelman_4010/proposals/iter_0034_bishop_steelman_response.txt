CRITIQUE: The suggestion to use a set for whitespace checking is misguided because it doesn't address the actual performance bottleneck. The `_skip_ws` function still needs to examine each character sequentially, so the `in` check doesn't reduce the overall time complexity from O(n) to O(1) — it just moves the constant factor from the loop body to the set membership test. Additionally, this approach would still require the function to iterate through the string character-by-character, which is inefficient for large amounts of whitespace.

STEELMAN: A better approach would be to precompute the longest prefix of whitespace characters starting at the given position and advance the index by that amount, rather than incrementing one character at a time. This can be done by scanning ahead in the string to find the first non-whitespace character, then advancing the position by that count, effectively skipping large blocks of whitespace in one operation.
