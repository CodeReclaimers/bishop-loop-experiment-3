One specific change to try is to use a more efficient string concatenation approach in `_parse_value` for building large strings during parsing. Specifically, we can use `out = out + "some string"` instead of `out += some_string` whenever possible. This avoids the overhead of re-creating the string on each append operation, which was causing the slowdown. The mechanism used to determine the optimal position in the string is not changed; it remains based on the current index `pos`.
