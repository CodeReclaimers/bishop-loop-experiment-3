A more efficient way to parse numbers would be to use a regular expression that matches the number format directly, rather than scanning each character for digits and whitespace separately. This would reduce the time complexity from O(n) to O(log n), where n is the length of the number. The modified `parse_number` function would look something like this:

```python
def _parse_number(text: str, pos: int) -> tuple[float | int, int]:
    match = _NUMBER_PATTERN.match(text, pos)
    if not match:
        raise JSONParseError(f"bad number at {pos}")
    s = match.group(0)
    pos = match.end()
    # Direct conversion with explicit handling to avoid float/int overhead
    if "." in s or "e" in s.lower():
        return float(s), pos
    # For integers, use int() directly but ensure no unnecessary parsing
    return int(s), pos
```

This approach relies on the regex pattern defined in `_NUMBER_PATTERN` to match the number format directly. This would improve performance because it avoids unnecessary character scanning and reduces the time complexity from O(n) to O(log n).
