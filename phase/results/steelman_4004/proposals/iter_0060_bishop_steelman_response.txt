CRITIQUE: The suggestion to use regex for number parsing is problematic because regex matching in Python has significant overhead compared to direct character iteration, especially for simple digit sequences. It would not actually reduce time complexity since the core issue is character-by-character scanning, not the method of scanning. Additionally, regex-based approaches are less predictable in performance and may introduce edge cases with backtracking or catastrophic backtracking on malformed inputs.

STEELMAN: The steelman is to precompile a regex pattern that matches valid JSON number formats (including integers, floats, and exponents) and use it to efficiently scan and extract the number substring, then convert that substring to a numeric type using direct parsing methods like `int()` or `float()`. This preserves the core idea of optimizing number parsing while avoiding regex overhead and maintaining correctness.

import re

# Precompile regex for number matching
_NUMBER_RE = re.compile(r'-?(?:0|[1-9]\d*)(?:\.\d+)?(?:[eE][+-]?\d+)?')

def _parse_number(text: str, pos: int) -> tuple[float | int, int]:
    # Use regex to scan the number
    match = _NUMBER_RE.match(text, pos)
    if not match:
        raise JSONParseError(f"bad number at {pos}")
    s = match.group(0)
    pos += len(s)
    if '.' in s or 'e' in s.lower():
        return float(s), pos
    return int(s), pos
