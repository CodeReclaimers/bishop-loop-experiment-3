CRITIQUE: The suggestion to use binary search on precomputed non-whitespace indices would fail because it doesn't account for the fact that the parser processes input sequentially and may need to skip varying amounts of whitespace at different positions. Additionally, building a list of all non-whitespace indices would be memory-inefficient and not actually faster than the current O(1) lookup approach. The binary search would also not be faster than the current loop, especially for small inputs.

STEELMAN: A better version would precompute a "skip table" that for each position in the input string, stores the index of the next non-whitespace character. This table can be built in linear time and used to jump directly to the next non-whitespace position, avoiding repeated character-by-character checks while maintaining correctness and efficiency.

def _build_skip_table(text: str) -> list[int]:
    n = len(text)
    skip_table = [0] * n
    skip_table[n - 1] = n
    for i in range(n - 2, -1, -1):

            skip_table[i] = skip_table[i + 1]
