This would incorrectly advance the position by only one character instead of skipping all leading whitespace. Additionally, `find()` is not guaranteed to be faster than the optimized Python loop, especially for small inputs or when whitespace is rare.
STEELMAN: The steelman version would use a hybrid approach: first check if there's any whitespace at all using `text.find(''.join(_WS_CHARS), pos)`; if found, use a fast loop to skip all consecutive whitespace characters, otherwise return the original position.
